## Контрольные вопросы

**1. Что такое Load Balancing и для чего он используется?**  
Load Balancing — распределение входящих запросов между несколькими серверами. Это помогает повысить производительность, доступность и устойчивость приложения.

**2. Почему крупные веб-сайты используют несколько серверов?**  
Чтобы обрабатывать большое количество запросов, распределять нагрузку, проводить обслуживание отдельных узлов и сохранять доступность при отказе одного из серверов.

**3. Какую функцию выполняет NGINX в данной работе?**  
NGINX работает как обратный прокси-сервер и балансировщик: принимает запросы на порту 80 внутри контейнера и перенаправляет их на один из трёх веб-серверов.

**4. Что такое алгоритм Round Robin?**  
Это алгоритм последовательного распределения запросов между серверами по очереди. В данной конфигурации он используется NGINX по умолчанию.

**5. Как работает параметр upstream?**  
`upstream` задаёт именованную группу серверов, между которыми NGINX распределяет запросы.

**6. Для чего используется директива proxy_pass?**  
Она задаёт адрес группы или сервера, куда NGINX передаёт запрос клиента.

**7. Что произойдёт, если один из серверов перестанет работать?**  
NGINX обнаружит ошибку при попытке отправить запрос на этот сервер. С учётом настроек повторной попытки он может направить запрос на другой доступный сервер. Первая попытка может вызвать небольшую задержку.

**8. Что такое отказоустойчивость (Fault Tolerance)?**  
Это способность системы продолжать предоставлять сервис при отказе отдельных компонентов, возможно с временным снижением производительности.

**9. Для чего используются параметры max_fails и fail_timeout?**  
`max_fails` задаёт допустимое количество неудачных попыток в период `fail_timeout`, после которого сервер временно считается недоступным. `fail_timeout` задаёт период учёта ошибок и время такого временного исключения.

**10. Какую роль выполняет Docker Compose?**  
Он описывает и запускает многоконтейнерное приложение: сервисы, образы, тома, порты, зависимости и параметры перезапуска.

**11. Чем балансировка нагрузки отличается от масштабирования серверов?**  
Балансировка распределяет запросы между уже имеющимися узлами. Масштабирование изменяет количество или ресурсы узлов: добавляет/удаляет серверы либо увеличивает/уменьшает их мощность. Эти подходы часто применяются вместе.

**12. Почему балансировка нагрузки важна для облачной инфраструктуры?**  
Она помогает равномерно использовать ресурсы, выдерживать рост трафика, повышать доступность приложений и обслуживать запросы при отказе отдельных экземпляров.
